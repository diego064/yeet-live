# Diego's AI Money Magnet — free, automated recreation of YEET Terminal

Same pages as the original (`zeuswasalaker/yeetterminal2`): Prestige, RAMBO,
PARI, RAMBO Calendar, Index WARI, Orange Swan, MEME LAB, Changelog.
Same RAMBO matching rule (confirmed, non-earnings event; contract printed
before the event and expiring on/after it).

What changed — this is the whole point of the recreation:

| Original | Diego's AI Money Magnet (this repo) |
|---|---|
| Paid Unusual Whales CSV uploads, by hand | Live Yahoo Finance pull, free, no API key |
| Hand-committed `data/snapshot.json` (Oct 2026) | `data/live_snapshot.json`, refreshed automatically |
| Prestige / WARI / Orange Swan from saved paid-flow files | Same pages computed from the live public options chain |
| GitHub Action only checked event pages for changes | GitHub Action refreshes the actual data every 15 min (weekdays) |
| Earnings dates in uploaded exports, not refreshed | Yahoo earnings calendar auto-added on every refresh |

## The honest limit on "real time"

There is **no free, legal, real-time options-flow feed**. Unusual Whales,
FlowAlgo and Cheddar Flow are paid because exchanges charge for real-time
options data. What Yahoo gives you free:

- US stock quotes delayed ~15 minutes, options chains refreshed through the day
- Volume, open interest, last price, implied volatility per contract
- Earnings calendar

What it does **not** give you:

- Tick-by-tick / real-time flow, or buy-vs-sell side — so this app never
  invents a side. "Unusual" here means **volume vs open interest on the
  public chain**: volume ≥ 100, premium ≥ $10,000, and volume ≥ open interest
  (or volume ≥ 500, or premium ≥ $100,000). Premium = volume × last price × 100.
- True whale identity. A big print is a research lead, not a trade signal.

If you later pay for a flow feed, only `live_data.fetch_ticker` needs to
change — the pages, matching and scoring stay the same.

## Run it

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Or refresh the data without opening the app:

```bash
python refresh.py   # writes data/live_snapshot.json
```

## Deploy free (Streamlit Community Cloud)

1. Push this folder to a GitHub repo.
2. Go to share.streamlit.io, New app → your repo → `app.py`.
3. That's it — no secrets needed. The app pulls Yahoo live on load and
   caches for 5 minutes; the GitHub Action in `.github/workflows/refresh.yml`
   also refreshes `data/live_snapshot.json` every 15 minutes on weekdays,
   so the first load is fast even before a live pull.

## Customise

- **Watchlist:** sidebar → Add ticker. Saved to `data/watchlist.json`.
  Default is 40 tickers (SPY/QQQ, semis, the original's most-printed names, GME/AMC).
  Scanning 40 tickers × 3 expiries takes ~30–60s on first load, then it's cached.
- **Events:** RAMBO → Add an event. Conference / analyst-day dates aren't in
  any free structured feed, so this is the one manual piece — saved to
  `data/events.json`. 53 confirmed events from the original are seeded there.
  Earnings dates are auto-added from Yahoo on every refresh.
- **Thresholds:** edit `MIN_VOLUME`, `MIN_PREMIUM`, `MAX_EXPIRIES_PER_TICKER`
  in `live_data.py`.

## Files

- `app.py` — all pages (Streamlit)
- `live_data.py` — Yahoo fetch, unusual detection, RAMBO match, WARI, PARI
- `refresh.py` — headless refresh for cron / GitHub Actions
- `data/events.json` — seeded confirmed events (from the original snapshot)
- `data/watchlist.json` — tickers scanned each refresh
- `data/live_snapshot.json` — generated by `refresh.py` / the app (git-ignored in spirit; committed by the Action)
- `.github/workflows/refresh.yml` — 15-min weekday refresh
